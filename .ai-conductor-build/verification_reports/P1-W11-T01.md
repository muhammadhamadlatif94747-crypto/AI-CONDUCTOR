## Scope decision stated up front (flagged per Build Protocol §8, not silently assumed)

Blueprint §21's mockup shows rich per-mission fields (workspace, files expected/modified, reconciliation status, acceptance contract). **The kernel does not yet have a persisted Mission/Step/Attempt object store** — that's later-phase orchestration work, not something P1 built. Fabricating those fields would be exactly the "fake/demo dashboard" the task contract explicitly forbids ("Do not use mocked state where real kernel state is required"). Instead this console shows what P1 actually has and what's actually true on disk: event history, chain integrity, outbox durability state, sequence counter — sourced through the real public APIs (`EventLog`, `AnchorStore`, `Outbox`, `SequenceAllocator`), nothing synthesized.

## Capability boundary design (AC-07 / Blueprint §16)

The kernel's only existing actor-authorization boundary today is `state::try_attempt_transition` (checked: `MissionStatus`/`StepStatus` only have structural `can_transition_to`, no actor check yet — that's the sole enforcement point that exists). The console's one mutation — request attempt cancellation — routes through this exact function as `TransitionActor::CancellationPath`, the same actor identity the transition table already reserves for cancellation requests. The console is granted no new bypass actor and cannot construct authorization it doesn't have (proven directly: `console_cannot_force_verification_engine_only_transitions`). Both outcomes — authorized and denied — are written to the real event log, never silently dropped (Blueprint §16: "reject, log, surface").

## Addendum — defect found during Phase 1 takeover audit (P1-W11-T01 scope)

**Found:** independent hands-on run of the compiled `console` binary
against a store directory that had never been created (not a
pre-existing tempdir, unlike every unit test's fixture) failed with
`I/O error: No such file or directory` on both `snapshot` and `cancel`
— contradicting the binary's own doc comment, which promises the
directory "will create, for cancel."

**Root cause:** `EventLog::open` (and the console's other store
constructors) create the *file* if missing but never the *parent
directory*. No existing unit test exercised a directory that didn't
already exist, so this gap was invisible to the accepted test suite.

**Fix:** `store_dir` is now created (`create_dir_all`) once at the top
of `bin/console.rs::main()`, before dispatching to either command —
the CLI process boundary, not the library. `console.rs`'s `snapshot()`
remains read-only by contract (querying must not have the side effect
of creating a directory); only the binary's own promised behavior
changed.

**Verified:** rebuilt, re-ran the binary by hand against two genuinely
fresh (never-existing) directories for both `snapshot` and `cancel` —
both now succeed as documented. Full suite re-run after the fix:
106/106 passing, 0 warnings. Scope: exactly one file changed
(`bin/console.rs`), confirmed via `git status`.

This does not reopen VG-P1-W11-T01's PASSED verdict (the task's actual
`done_when` criteria concerned the library's rendering and capability
enforcement, both still correct) — it is a genuine but narrow CLI
ergonomics defect, found and fixed during this takeover audit, recorded
here rather than silently folded into the original report.
