# VG-P3-W02-T01 — VirtualClock

**Task:** P3-W02-T01 — Implement the virtual clock required for instant
deterministic time-dependent tests (Phase Manifest §7.3 P3-W02; Blueprint
§10.2's hard architecture rule, §28.5).

**Status:** ACCEPTED

## Starting condition
`event.rs`'s `ClockSource::{Real,Virtual}` has tagged every event with
which kind of clock produced its timestamp since P1, but nothing
implemented either kind — confirmed by grep before writing any code (no
`Clock` trait, no `RealClock`, no `VirtualClock` anywhere; no
`SystemTime::now()` call anywhere in the crate at all, meaning even the
sanctioned real-clock read didn't exist yet).

## Implementation
New module `PROJECT/crates/conductor-kernel/src/clock.rs`:

- `Clock` trait: `now_ms(&self) -> u64`, `source(&self) -> ClockSource`,
  plus a `now_ms_and_source` convenience default method.
- `RealClock` wraps the crate's one legal `SystemTime::now()` call.
- `VirtualClock` starts at a caller-chosen value (`VirtualClock::at`) and
  advances only when explicitly told to (`advance(Duration)`) — Blueprint
  §28.5's "clock advances 30s" made concrete. Backed by `AtomicU64`,
  reusing the same pattern already established in
  `mutation_attribution.rs`'s nonce counter rather than introducing a new
  interior-mutability style.

**Deliberately not done:** existing call sites (`console.rs`,
`person_decision.rs`) were not retrofitted to take a `Clock` parameter —
both already correctly avoid reading time directly by taking `now_ms` as
a plain caller-supplied value, and reopening two already-ACCEPTED modules
to change their signatures wasn't asked for and isn't required by the
hard rule (which is about who's allowed to *read* the clock, not about
every function's parameter shape).

## Tests (10 new, all passing)
`real_clock_is_sanity_bounded_against_real_wall_time` (the one place in
this crate a comparison against real time is legitimate, since that's
`RealClock`'s whole purpose), `real_clock_source_is_real`,
`virtual_clock_starts_at_the_specified_value`,
`virtual_clock_default_start_is_zero`,
`advance_moves_the_clock_forward_by_exactly_the_given_duration` (exact
value, not tolerance-based), `multiple_advances_accumulate_correctly`,
`advance_never_actually_waits` (a one-year virtual advance completes in
under 50ms of real time), `virtual_clock_source_is_virtual`,
`both_clocks_work_correctly_through_a_trait_object` (both concrete types
proven usable behind `Box<dyn Clock>`, not just directly),
`now_ms_and_source_returns_both_values_together`.

## Crate-wide clock audit (required by this task's contract)
```
grep -rn "SystemTime::now|Instant::now|Utc::now|Local::now" *.rs
```
Every production-code hit is `clock.rs:58` (`RealClock::now_ms`) — the
one sanctioned direct read. All other hits are test-only: `clock.rs`'s
own tests sanity-checking `RealClock` against real time (legitimate, as
above), and `Instant::now()` calls in `clock.rs`'s and `provider.rs`'s
test modules measuring real elapsed wall-clock time to prove something
completes instantly (not used for any time-dependent *logic* — the same
pattern P3-W01's own tests already established). No second, competing
timestamp-generation mechanism exists anywhere in the crate.
