# VG-P2-W04-T01 — Protected Succeeded Transition

**Task:** P2-W04-T01 — The Reconciliation Engine must never set `Succeeded`
(Phase Manifest §6.3 P2-W04; Blueprint §4.3, Invariant 14).

**Status:** ACCEPTED

## Starting condition
P1's `state.rs` already restricted the `Running/Unknown → Succeeded` edges
to `TransitionActor::VerificationEngine` (confirmed by reading the existing
`try_attempt_transition` gate and its P1 tests before writing any code) —
the structural half of Invariant 14 already existed. What was missing:
Blueprint §4.3's outcome → next-action mapping was never implemented
anywhere, and nothing in the codebase directly tied a `ReconciliationOutcome`
(P2-W03) to that gate to prove the two compose correctly at the boundary
where they actually meet.

## Implementation
Added to `PROJECT/crates/conductor-kernel/src/reconciliation.rs` (no new
file — this extends the module P2-W03 built):

- `recommended_attempt_status(outcome: &ReconciliationOutcome) -> Option<AttemptStatus>`
  implementing Blueprint §4.3's table: `ExpectedChange` → `None` (defers to
  the Verification Engine — there is no `AttemptStatus` value in this crate
  that means "reconciliation thinks this succeeded"); every other outcome
  (`NoChange`, `UnexpectedChange`, `PartialChange`, `UserChangeDetected`,
  `Conflict`) → `Some(AttemptStatus::Failed)`. Downstream routing specific
  to each of those five (targeted repair, mission pause, etc.) is
  explicitly out of scope — P2-W05/P2-W06/P2-W07's job.
- No changes to `state.rs`'s existing authorization gate — this task
  reinforces Invariant 14 by proving reconciliation cannot circumvent it,
  not by touching the gate itself (`forbidden_actions` in the contract
  explicitly prohibited weakening it).

## Tests (4 new, all passing)
- `recommended_attempt_status_never_yields_succeeded_for_any_outcome` —
  exhaustive over all six `ReconciliationOutcome` variants, the Phase
  Manifest's literal required direct test ("reconciliation result ≠
  Succeeded transition"), not a spot-check.
- `expected_change_defers_rather_than_recommending_any_status` —
  `ExpectedChange` → `None` specifically, not any status at all.
- `every_non_expected_change_outcome_recommends_failed` — the other five
  variants each map to `Some(Failed)`.
- `expected_change_can_only_become_succeeded_through_the_verification_engine_actor`
  — the real integration test: takes an actual `reconcile()` result
  (`ExpectedChange`, the case closest to success), confirms
  `recommended_attempt_status` proposes nothing for it, then attempts
  `try_attempt_transition(actor, Running, Succeeded)` for every
  `TransitionActor` and confirms only `VerificationEngine` succeeds —
  proving the P2-W03 and P1 modules compose correctly where they meet,
  not just correct in isolation.
