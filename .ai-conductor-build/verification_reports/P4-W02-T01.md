# VG-P4-W02-T01 — Evidence Production

**Task:** P4-W02-T01 — Verification must use actual evidence with the
required provenance/freshness semantics (Phase Manifest §8.3 P4-W02;
Blueprint §4.5).

**Status:** ACCEPTED

## Starting condition
Nothing in the crate implemented structured Evidence, provenance
classification, or freshness computation; confirmed by grep before
writing any code. P4-W01's `StageOutcome` existed as a real, accepted
source of stage results for `Evidence::from_stage_outcome` to consume.

## What's verbatim from the Blueprint and what's this task's own call
`EvidenceProvenance` (six variants) and `Reproducibility`
(`Deterministic | Flaky | Unknown`) are reproduced exactly as Blueprint
§4.5 states them. `ObservationType` and `IntegrityLevel` are referenced
by §4.5's `Evidence` struct but their variants are not enumerated
anywhere read for this task — the sets defined here are stated, in the
module doc comment and here, as this task's own reasonable
interpretation, not presented as if found verbatim in the text.
`Evidence::result: bool` is likewise an explicit, justified addition
beyond Blueprint's minimal code snippet: evidence with no recorded
observed outcome can't usefully satisfy anything, and §8's Mission
Acceptance Contract criteria compare against an actual result.

## Implementation
New module `PROJECT/crates/conductor-kernel/src/evidence.rs`:

- `Evidence` stores `produced_at_ms` (a point in time) rather than
  Blueprint's literal `freshness: Duration` field — a fixed `Duration`
  captured once would go stale the moment real time passes, defeating
  the point of a freshness check. Documented explicitly as a deliberate,
  small deviation for correctness, not a silent reinterpretation.
- `freshness_relative_to`/`is_fresh` take an explicit `now_ms`; no method
  anywhere in this module reads the system clock directly — confirmed by
  a crate-file grep audit (`SystemTime::now`/`Instant::now`: zero matches
  in `evidence.rs`), the same method used for every prior clock-related
  task since P3-W02.
- `Evidence::matches(provenance, max_freshness, execution_id, now_ms)`
  makes Blueprint §8's `required_evidence` check real: wrong provenance,
  staleness, a mismatched `execution_id`, or a failed underlying result
  each independently fail the match — proven by four separate tests
  (`wrong_provenance_alone_fails_the_match`,
  `staleness_alone_fails_the_match`,
  `wrong_execution_id_alone_fails_the_match`,
  `a_failed_underlying_result_fails_the_match_even_with_correct_provenance_and_freshness`),
  not just a single all-correct-passes case.
- `Evidence::from_stage_outcome` constructs real Evidence from a real
  P4-W01 `StageOutcome`, connecting the pipeline's actual stage results
  to real evidence rather than leaving them as a separate concept.
  `result` reflects the stage's actual status — proven for `Passed`,
  `Failed`, and, importantly, `SkippedDueToEarlierFailure` (a skipped
  stage is evidence of nothing having run and must not be treated as a
  pass — a case worth its own explicit test, not assumed obvious).
