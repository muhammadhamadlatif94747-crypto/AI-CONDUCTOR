# VG-P2-W07-T01 — Person Decision Path

**Task:** P2-W07-T01 — Implement the four-way person decision UI required
by the Blueprint; functional decision UI, not polished Mission Mode
(Phase Manifest §6.3 P2-W07; Blueprint §4.3, §21, AC-07; Invariant 11).

**Status:** ACCEPTED

## Starting condition
P2-W06 produces `ConflictReason` as data but nothing renders it for a
person or captures their choice; confirmed by grep before writing any
code. P1-W11's `console.rs` already established the exact pattern to
reuse for this — real `EventLog` read/write, no mocked state, every
outcome (including denial) written as a real event — rather than this
task inventing a second persistence style.

## Implementation
New module `PROJECT/crates/conductor-kernel/src/person_decision.rs`:

- `PersonDecision` reproduces Blueprint §4.3's four-way choice verbatim
  (`KeepUserVersion`, `KeepAiVersion`, `Merge`, `ReviewDiff`) — no fifth
  "auto-resolve" option exists, so Invariant 11 is upheld by construction,
  not by a runtime check that could be bypassed.
- `describe_conflict(&ConflictReason) -> String` renders the *actual*
  evidence — real changed paths, real conflicting regions with their line
  ranges — not a generic placeholder. Proven by tests asserting the real
  values (`"auth.ts"`, `"model.py"`, the specific line numbers `40`/`45`)
  appear in the output, not just that the string is non-empty.
- `render_decision_prompt(&ConflictReason) -> String` is the actual text a
  person would see: evidence + all four numbered options, mirroring
  `console.rs::render`'s plain-text style exactly.
- `record_person_decision(store_dir, context, reason, decision, now_ms)`
  mirrors `console::request_attempt_cancellation` precisely: same
  `StorePaths`, same `EventLog::open`/`NewEvent` call shape, `now_ms`
  caller-supplied (no direct system-clock read — AC-12, the crate-wide
  hard rule). Writes the decision *and* the evidence it responds to, so
  the log alone reconstructs why the person chose what they chose.

**Scope boundary held deliberately:** this task records what the person
chose. It does not execute the choice — no merge write, no "keep AI
version" file write — because the workspace mutation lock and a
merge-executor were both explicitly out of scope for P2-W06 and remain
unbuilt. It also does not drive any `MissionStatus` transition, for the
same reason P2-W06 didn't (re-confirmed: `state.rs` still has no
actor-authorization wrapper for mission-level transitions).
