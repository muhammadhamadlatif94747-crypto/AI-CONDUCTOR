# VG-P5-W02-T01 — Executor Capability Snapshot

**Task:** P5-W02-T01 — Record executor identity, version/commit,
capabilities, workspace behavior, lifecycle semantics, and verification
provenance (Phase Manifest §9.3 P5-W02).

**Status:** ACCEPTED

## Environment constraint carried forward from P5-W01
No real executor is available in this sandbox. This task's own tests
capture a snapshot from `FakeExecutionAdapter` (P5-W01) with caller-
supplied workspace-behavior and lifecycle-semantics values — the
*mechanism* is real and tested; the *content* is clearly a test double's,
never presented as data about Aider or Jcode.

## Starting condition
Nothing in the crate implemented a durable capability snapshot record;
confirmed by grep before writing any code. P5-W01's `ExecutionAdapter`/
`ExecutorIdentity`/`CapabilitySnapshot`, P4-W02's `Evidence` types, and
P1's `EventLog` all existed as the real primitives this task composes.

## Implementation
New module `PROJECT/crates/conductor-kernel/src/executor_capability_snapshot.rs`:

- `ExecutorCapabilitySnapshotRecord` combines all six of Phase Manifest
  §9.3's named dimensions: identity + version/commit (`ExecutorIdentity`,
  P5-W01), capabilities (`CapabilitySnapshot`, P5-W01), workspace
  behavior (`WorkspaceBehaviorNotes`, new), lifecycle semantics
  (`LifecycleSemanticsNotes`, new), and verification provenance
  (`EvidenceProvenance`/`IntegrityLevel`, reused directly from P4-W02).
- `capture_snapshot` pulls identity and capabilities directly from a real
  `&dyn ExecutionAdapter` — proven by
  `capture_snapshot_pulls_identity_and_capabilities_from_a_real_adapter_through_the_trait_object`,
  which goes through the trait object, not the concrete
  `FakeExecutionAdapter` type.
- `WorkspaceBehaviorNotes`/`LifecycleSemanticsNotes` fields are
  `CapabilityValue` tri-states (P5-W01's type, reused directly) — proven
  by `unobserved_workspace_and_lifecycle_fields_are_unknown_not_silently_favorable`
  that an unobserved behavior stays `Unknown`, never silently assumed
  `Supported` or `Unsupported`.
- `record_executor_capability_snapshot` writes a real event via the same
  `EventLog::open`/`NewEvent` path `console.rs`/`person_decision.rs`
  already established, `now_ms` caller-supplied (AC-12, confirmed by
  grep — zero direct clock reads in this module). Proven by
  `record_executor_capability_snapshot_writes_a_real_readable_event`,
  which writes to a real temporary store, reopens the log, and asserts
  the recorded content — including nested workspace-behavior and
  lifecycle-semantics fields — matches exactly.

**Scope boundary held deliberately:** `execution_adapter.rs` (P5-W01) was
not reopened to add workspace-behavior/lifecycle-semantics probe methods
to the trait — those dimensions require running real scenarios against a
real executor and observing the result (P5-W03/W04's job), not a
queryable property the adapter itself can report; adding speculative
probe methods now, with nothing real to call them against, was avoided.
