## Scope decision stated up front
This task delivers the isolation primitive only: create, tear down, and
crash-safe recovery of an attempt's Git worktree. It does NOT implement
baseline capture (P2-W02), the Reconciliation Engine (P2-W03), the
protected `Succeeded` transition (P2-W04), or the two-phase merge lock
(Invariant 13, later work) — merging an attempt's result into the live
workspace is deliberately absent here; until that later work exists, an
attempt workspace's changes simply stay in the attempt workspace. This
matches the task contract's explicit non-goals.

## Design
New module `PROJECT/crates/conductor-kernel/src/worktree.rs`:
`WorktreeManager::create`/`remove`/`list_registered`, `AttemptWorkspace`,
`WorktreeError`. Backed by real `git worktree add|remove|prune|list`
invocations via `std::process::Command` — the first module in this
crate with an external-process dependency rather than pure filesystem
I/O, per Blueprint §5's explicit choice of `git worktree` as the
mechanism ("cheap, fast, already part of Git, no new dependency").

- `create()` always places the new worktree under a caller-supplied
  `workspaces_root`, structurally distinct from the live repository —
  not something each caller has to remember to arrange.
- Checkouts are `--detach`, avoiding Git's "branch already checked out"
  refusal and keeping an attempt's worktree independent of whatever
  branch the live repo itself has checked out.
- `remove()` always prunes stale registry entries first, then removes
  the directory only if it still exists — this is what makes it safe
  against the crash scenario below.
- `list_registered()` reads Git's own `worktree list --porcelain`
  output directly rather than maintaining an independent ledger that
  could drift from what Git actually believes exists — this is the
  function a restart would call to rediscover in-flight attempts.

## Tests (10 new, all real Git repositories — nothing mocked)
- `create_produces_a_path_distinct_from_the_live_repo`
- `create_does_not_modify_the_live_repos_tracked_files`
- `create_does_not_change_the_live_repos_git_status`
- `writes_inside_the_attempt_workspace_never_touch_the_live_repo` — the
  sharpest, most literal proof of Blueprint §5's requirement: mutates
  and creates files inside the attempt workspace (simulating what Aider
  would do) and confirms none of it is observable in the live repo.
- `worktree_is_checked_out_at_the_requested_base_commit_and_later_live_commits_do_not_leak_in`
  — proves isolation runs both directions: the live repo advancing after
  attempt creation doesn't leak into the pinned attempt workspace.
- `remove_tears_down_the_worktree_and_the_live_repo_is_unaffected`
- **`remove_recovers_from_a_worktree_directory_deleted_out_from_under_git`**
  — the required failure-injection proof (Phase Manifest §6.4:
  "unexpected process exit"). Deletes the worktree directory directly on
  disk without going through Git (simulating a crash mid-teardown or an
  external deletion), confirms Git's registry is genuinely left stale
  (not a no-op test), then confirms `remove()` recovers cleanly and the
  manager remains fully usable for a subsequent attempt afterward.
- `list_registered_reflects_reality_for_restart_recovery`
- `two_concurrent_attempt_workspaces_are_fully_independent`
- `create_fails_closed_with_captured_stderr_on_an_invalid_base_commit` —
  confirms Git's real stderr is surfaced, not swallowed, on failure.
