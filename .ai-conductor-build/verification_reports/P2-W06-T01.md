# VG-P2-W06-T01 — Conflict Detection

**Task:** P2-W06-T01 — Implement conflict detection; Conflict must halt
rather than silently resolve (Phase Manifest §6.3 P2-W06; Blueprint §5,
§26.2/Invariant 13, §5.1, Invariant 11).

**Status:** ACCEPTED

## Starting condition
P2-W05 produces `ConflictRegion` as data but decides nothing; nothing in
the crate implemented Invariant 13's merge-time re-check (comparing the
original baseline against the live workspace immediately before a merge);
confirmed by grep before writing any code. Also confirmed: `state.rs`
currently exposes no actor-authorization wrapper for `MissionStatus`
transitions at all (only `try_attempt_transition` exists) — this shaped
the scope decision below.

## Implementation
New module `PROJECT/crates/conductor-kernel/src/conflict.rs`:

- `check_merge_safety(original_baseline, live_at_merge_time) -> MergeCheckResult`
  implements Invariant 13's re-check using `Baseline::diff` (P2-W02).
  Only `Modified` and `Removed` paths count as drift; `Added` paths are
  deliberately excluded, directly citing Blueprint §5.1's table row for
  newly-created untracked files ("not part of the baseline comparison;
  left alone"). Proven by a dedicated test
  (`a_newly_added_path_alone_is_safe_not_conflict`), not just implemented
  and asserted in a comment.
- `decide_merge(merge_check, attributions) -> MergeDecision` composes
  Invariant 13's signal with P2-W05's `ConflictRegion` signal. `Proceed`
  is reachable in exactly one of the four combinations (both signals
  clear) — proven by an exhaustive sweep
  (`proceed_is_reachable_only_in_the_safe_and_no_conflict_cell`), not
  inferred from testing each signal in isolation.
- `MergeDecision::Halt(ConflictReason)` carries the actual changed paths
  and/or conflicting regions, not a bare flag — so a future caller
  (P2-W07's four-way UI) has real evidence to show the person, proven by
  two dedicated tests rather than assumed from the type signature alone.

**Scope boundary held deliberately:** this task decides Proceed vs Halt.
It does not drive any `MissionStatus` transition (no gate exists yet to
compose against, unlike P2-W04 which had `try_attempt_transition` ready),
does not implement the four-way person decision UI, does not perform the
merge write, and does not implement the workspace mutation lock — all
explicitly out of scope and noted in the contract rather than silently
assumed solved.
