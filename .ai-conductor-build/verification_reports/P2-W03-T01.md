# VG-P2-W03-T01 — Diff-Aware Reconciliation Engine

**Task:** P2-W03-T01 — Implement and unit-test the Reconciliation Engine
(Phase Manifest §6.3 P2-W03; Blueprint §4.3, §6).

**Status:** ACCEPTED

## Starting condition
P2-W02 (baseline.rs) produces a `Baseline` and a `diff`/`diff_full`
comparison, but nothing in the crate turns that comparison into Blueprint
§4.3's `ReconciliationOutcome`, and no independently-callable reconciliation
function existed anywhere — confirmed by grep before writing any code.

## Implementation
New module `PROJECT/crates/conductor-kernel/src/reconciliation.rs`:

- `ReconciliationOutcome` reproduces Blueprint §4.3's enum verbatim, all
  six variants (`NoChange`, `ExpectedChange`, `UnexpectedChange`,
  `PartialChange`, `UserChangeDetected`, `Conflict`).
- `ExpectedOperation { files, intent }` matches Blueprint §4.4's
  `expected_operation` shape.
- `reconcile(before: &Baseline, after: &Baseline, expected: &ExpectedOperation) -> ReconciliationOutcome`
  is a pure, deterministic function implementing steps 1-5 of Blueprint
  §6's algorithm: empty diff → `NoChange`; every expected file changed and
  nothing else → `ExpectedChange`; a proper non-empty subset of expected
  files changed and nothing else → `PartialChange`; anything outside the
  expected set changing (regardless of whether expected files also
  changed) → `UnexpectedChange`, treated conservatively per §4.3's own
  wording.
- `change_for_path` exposes the underlying per-path `PathChange` for
  callers that want region-level detail behind an outcome.

**Scope boundary held deliberately:** `UserChangeDetected` and `Conflict`
are defined in the enum for Blueprint-fidelity but `reconcile()` never
produces them — those require mutation attribution (Blueprint §4.6, P2-W05)
and region-overlap conflict detection (P2-W06), neither of which exists yet.
Approximating them from file-level data alone would be false-confidence
evidence, exactly what Blueprint §7's `RequirementVerificationClass`
distinction exists to prevent. Left for P2-W05/P2-W06 to wire in once the
data they need actually exists.

**Restart-safety** (Blueprint §6: "reconciliation itself must be safe to
interrupt"): satisfied by `reconcile()` having no internal state and no I/O
of its own, rather than by checkpointing intermediate steps. A crash
mid-reconciliation means nothing was written yet; restarting is simply
calling the same pure function again against the same durable inputs (a
previously captured `Baseline` and a fresh re-capture). This is proven
directly by
`identical_inputs_after_a_simulated_restart_produce_the_identical_outcome`,
not just asserted.

`reconcile()`'s return type has no path to `AttemptStatus::Succeeded` at
all — it returns only `ReconciliationOutcome`, upholding Invariant 14
structurally (nothing in this function *can* set that status) rather than
by convention.

## Tests (12 new, all passing)
`identical_baselines_produce_no_change`,
`exactly_the_expected_file_changing_is_expected_change`,
`all_expected_files_changing_together_is_expected_change`,
`one_of_two_expected_files_changing_is_partial_change`,
`an_unrequested_file_changing_is_unexpected_change`,
`expected_file_changing_alongside_an_unexpected_one_is_still_unexpected_change`,
`a_change_with_an_empty_expected_operation_is_unexpected_change`,
`added_and_removed_files_are_classified_the_same_as_modified_files`,
`empty_baselines_with_nothing_expected_is_no_change`,
`identical_inputs_after_a_simulated_restart_produce_the_identical_outcome`
(Phase Manifest §6.4's "restart during reconciliation"),
`change_for_path_exposes_the_underlying_classification`,
`reconcile_never_touches_any_attempt_status_type` (structural witness test).
