# VG-P2-W02-T01 — Baseline Capture

**Task:** P2-W02-T01 — Capture the expected baseline before execution
(Phase Manifest §6.3 P2-W02; Blueprint §4.4, §4.6).

**Status:** ACCEPTED

## Starting condition
P2-W01 (worktree.rs, prior commits) produces an isolated `AttemptWorkspace`
but does not record what was in it before an attempt runs. Blueprint §4.4's
evidence shape shows `baseline` as a per-file content-hash map captured up
front; §4.6 phrases capture and later diffing as two distinct steps. Neither
existed anywhere in the crate before this task — confirmed by grep before
writing any code.

## Implementation
New module `PROJECT/crates/conductor-kernel/src/baseline.rs`:

- `Baseline::capture(workspace_root)` walks the filesystem and records a
  sha256 content hash per regular file, keyed by path relative to the
  workspace root — reusing the crate's existing hashing convention
  (`event::hex_encode`, already used by `event.rs`/`chain_anchor.rs`)
  rather than introducing a second one.
- `.git` at the workspace root is excluded **regardless of file type**.
  This mattered in practice, not just in principle: in the *main*
  repository `.git` is a directory, but inside a `git worktree add`
  checkout it is a small *file* (a `gitdir:` gitlink). The first
  implementation only excluded the directory form and was caught by the
  worktree-integration test below — `.git` leaked into the baseline as a
  captured "file" until the exclusion was made type-agnostic. Fixed, and
  a dedicated unit test (`dot_git_as_a_gitlink_file_is_also_excluded`)
  now covers the gitlink-file form directly rather than relying solely on
  the integration test to catch a regression.
- `Baseline::diff` / `diff_full` compare two baselines and report
  `Added`/`Removed`/`Modified { before, after }`/`Unchanged` per path —
  the primitive Invariant 13's live-workspace re-check and P2-W03's
  reconciliation will consume; this task does not implement either of
  those policies, only the comparison primitive.
- Capture is a pure read (verified directly, not just asserted).

## Tests (10 new, all passing)
`captures_a_hash_for_every_regular_file`,
`dot_git_directory_is_excluded`,
`dot_git_as_a_gitlink_file_is_also_excluded`,
`identical_content_produces_the_same_hash_deterministically`,
`a_single_byte_change_produces_a_different_hash`,
`capture_is_a_pure_read_and_never_mutates_the_workspace`,
`recapture_with_no_changes_produces_an_empty_diff`,
`diff_reports_modified_added_and_removed_paths`,
`modified_change_carries_both_before_and_after_hashes`,
`baseline_from_a_worktree_created_by_p2_w01_captures_its_checked_out_content`
(the last one is a real integration test against `worktree.rs`: creates an
actual `git worktree`-backed `AttemptWorkspace` and captures its baseline —
this is the test that caught the gitlink-file gap above; it was not a
theoretical edge case).

All `done_when` criteria met: per-file content hashing keyed by relative
