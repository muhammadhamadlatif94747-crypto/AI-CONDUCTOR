# VG-P1-W07-T01 — Idempotency-Key Store (Local Retry Detection)

**Task:** P1-W07-T01 — Idempotency-key store, per Blueprint §10.5/§20 and
AC-11 §4's two-artifact separation requirement.

**Status:** ACCEPTED

## Implementation
Two distinct modules, per AC-11 §4 (which explicitly forbids merging them):

- `idempotency.rs` — the `IdempotencySupport` classification model
  (`ServerSideGuaranteed` / `Unknown` / `NotIdempotent`, default `Unknown`
  per Blueprint §10.5), `decide_on_ambiguous_outcome()` encoding the
  §10.5 decision tree, and `safe_to_skip_retry()` — the single, narrow
  function where a local "already applied" signal and a provider
  classification are allowed to combine.
- `idempotency_store.rs` — `IdempotencyStore`, built on the P1-W05
  `AtomicStore` primitive: `has_already_applied`, `get`,
  `record_applied` (idempotent no-op on identical replay, fails closed
  on a conflicting outcome for the same key). `IdempotencyRecord` has
  exactly two fields (`key`, `outcome`) — no classification field.

## AC-11 separation — how it's enforced, not just asserted
- `idempotency_store.rs` contains no reference to `IdempotencySupport`
  anywhere in its own API surface (only in one test, which imports it
  from `idempotency` deliberately to prove the cross-module property).
- `tests::record_type_carries_no_classification_field` — destructures
  `IdempotencyRecord { key, outcome }` by name; a future added field
  (e.g. a smuggled-in classification) fails to compile against this
  pattern, a compile-time trip wire rather than a comment.
- `tests::local_applied_flag_never_upgrades_classification` — exhaustive
  over all 3×2 (classification × applied-locally) combinations:
  `safe_to_skip_retry` is true in exactly one of the six.
- `tests::local_store_recording_never_makes_an_unknown_provider_safe_to_skip`
  — end-to-end proof combining both real modules: a key IS recorded
  applied, provider classification is `Unknown`, `safe_to_skip_retry`
  still returns `false`.
