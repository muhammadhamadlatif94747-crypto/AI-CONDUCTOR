# VG-P3-W01-T01 — FakeProvider

**Task:** P3-W01-T01 — Implement a controllable fake provider with the
Blueprint-required fault menu (Phase Manifest §7.3 P3-W01; Blueprint
§10.1, §10.2).

**Status:** ACCEPTED

## Starting condition
Nothing in the crate implemented any provider abstraction; confirmed by
grep before writing any code. This is the first module of Phase 3.

## Implementation
New module `PROJECT/crates/conductor-kernel/src/provider.rs`:

- `ProviderRequest`/`ProviderResult` reproduce Blueprint §10.1's thickened
  fields. `capability_snapshot`/`raw_metadata`/`sanitized_metadata` are
  typed as `serde_json::Value` passthroughs rather than Section 10.3's
  full capability-registry shape — designing that registry is explicitly
  not this task's job.
- `FakeBehavior` reproduces Blueprint §10.2's ten variants verbatim.
- `FakeProvider` is script-driven: `push_behavior`/`push_behaviors` queue
  behaviors FIFO; `send` consumes exactly one per call. An empty script
  fails closed (`ProviderError::ScriptExhausted`) rather than silently
  defaulting to `Success` — matching this crate's established fail-closed
  discipline (baseline.rs, worktree.rs, mutation_attribution.rs).
- `DuplicateResponse` replays the *actual* prior successful result's
  `provider_response_id` (not a fabricated new one), and fails closed
  (`ProviderError::NoDuplicateAvailable`) if no prior success exists.
- `SlowResponse`'s `Duration` is recorded on the result
  (`simulated_delay`) but never slept on — no direct clock use anywhere
  in the module (AC-12).

**Deliberate, flagged deviation:** Blueprint §10.1 specifies `async fn
send()`. No async runtime exists anywhere in this crate (every module
from Phase 0 through Phase 2 is synchronous), so `send` is implemented
synchronously instead — documented in the module doc comment and the task
contract, not silently diverged from without saying so. Whichever future
task wires in a real, network-bound provider adapter will need to revisit
this.

## Tests (9 new, all passing)
`success_produces_an_ok_result_with_a_response_id`,
`each_failure_behavior_produces_its_own_distinguishable_error_variant`
(Timeout/RateLimited/MalformedOutput/Disconnect/Crash, each asserted as
its own variant, not just "is an error"), `partial_output_carries_the_partial_content`,
`invalid_tool_request_carries_details`,
`slow_response_records_the_delay_without_sleeping` (directly timed —
asserts real elapsed wall-clock time stays under 50ms despite a
120-second simulated delay), `duplicate_response_replays_the_prior_successful_response_id`,
`duplicate_response_with_nothing_to_duplicate_fails_closed`,
`an_empty_script_fails_closed_rather_than_defaulting_to_success`,
`scripted_behaviors_are_consumed_in_the_exact_order_queued` (proves
FIFO ordering directly, including that a 4th call after exhaustion still
fails closed rather than wrapping around).
