## Implementation
New module `PROJECT/crates/conductor-kernel/src/execution_adapter.rs`:

- `ExecutorIdentity`, `CapabilitySnapshot` (13 named capabilities),
  `ExecutionRequest`, `ExecutionState` (9 variants), `FinalizationClaim`
  (4 variants, a genuinely distinct type from `ExecutionState` — not a
  reused enum), `FailureCategory` (10 variants), `Observation`,
  `CancellationReport`, `EvidenceRefs` — all reproduced field-for-field /
  item-for-item from the contract document.
- `CapabilityValue` is a tri-state (`Supported`/`Unsupported`/`Unknown`),
  not a `bool`/`Option<bool>` that would conflate "known absent" with
  "never checked" — directly proven by
  `unknown_capability_never_silently_defaults_to_supported_or_unsupported`.
- `ExecutionRequest.correlation` reuses P1's `CorrelationContext`
  directly rather than a second identifier scheme — proven by
  `execution_request_reuses_correlation_context_directly`.
- **Hard Authority Rules upheld structurally**: this module has zero
  references to `crate::state` or `crate::conflict` anywhere in it
  (confirmed by grep — the only hits are the module's own doc comment
  explaining this), so the `ExecutionAdapter` trait has no method
  capable of setting `AttemptStatus::Succeeded`, authorizing a merge, or
  touching `MergeDecision` — not because of a runtime check, but because
  nothing in the trait's signature can reach those types at all.
- `FakeExecutionAdapter` is a scripted test double (mirroring
  `provider.rs`'s `FakeProvider` design), proven to implement the full
  trait purely through `Box<dyn ExecutionAdapter>` — not by calling its
  concrete methods directly.
